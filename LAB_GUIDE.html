Architecture Blueprint

Why Lab 4.5 Exists: The Two-Tier System

In an enterprise financial institution, an AI copilot cannot simply expose a Python web server directly to corporate users. Enterprise banking policies demand enterprise ingress security: single regulated entry point, cryptographic bearer token verification, per-user sliding window rate limiting, global concurrency controls, and high-availability error masking.

Lab 4.5 builds the complete two-tier system chosen in our Lab 4.2 Architecture Decision Record (ADR): a Java Spring Boot AI Gateway (port 8080) that serves as the hardened enterprise gatekeeper, and a Python FastAPI Orchestrator (port 8090) that deterministically routes customer prompts to three specialist agents (Policy, Transaction, and Eligibility) without direct external exposure.

🛡️
Java Gateway (Port 8080)
Single regulated entry point. Enforces Bearer authentication, OWASP input validation, token bucket rate limiting (429), and proxy forwarding with HTTP 503 circuit breaking.
🧭
Python Orchestrator (Port 8090)
Pure routing brain. Evaluates incoming prompts using strict keyword precedence (Eligibility > Transaction > Policy) and dispatches to isolated specialist agents.
🔌
Internal MCP Tool Bus
Specialists invoke Java banking tools over HTTP JSON-RPC at POST /mcp (searchPolicies, getRecentTransactions, getCustomerProfile) to assemble grounded answers.
Notice — No LLM Call in This Lab

Lab 4.5 intentionally contains no large language model invocations. In enterprise engineering, the integration plumbing, transport resilience, auth boundaries, deterministic routing, and protocol contracts must be verified independently before introducing non-deterministic model generation. Module 5 will plug the LLM into these exact specialist handlers.

Core Theory

4 Concepts That Underpin This Architecture

Concept 1 of 4

🛡️ Gateway Pattern — Java as the Gatekeeper

The API Gateway Pattern establishes a single, strongly governed entry point for all client communications. Cross-cutting concerns—authentication, token validation, OWASP input sanitization, rate limiting, and admission control—are completely enforced before a request reaches core business routing.

In this system, relationship managers (RMs) connect exclusively to the Java Gateway at http://localhost:8080/v1/copilot/query. The Python orchestrator has no public exposure; it runs as an internal microservice. If a request lacks a valid Bearer token, it is immediately terminated with an HTTP 401. The Python process never expends CPU cycles or logs unauthenticated traffic.

BFSI Real-World Equivalent
🏦 RBI & NPCI Unified Payments Interface (UPI) Gateway

Every UPI transaction initiated across PhonePe, Google Pay, or Paytm does not connect directly to the beneficiary bank's core accounting system. All requests first hit NPCI's central gateway. NPCI performs cryptographic device fingerprinting, biometric/PIN pre-validation, and fair-use rate limiting.

Only clean, authorized requests are forwarded to the individual bank's Core Banking Solution (CBS). Our Java Spring Boot gateway serves the exact same role as NPCI: guarding the downstream specialized services.

Concept 2 of 4

⚡ Proxy & 503 Failure Mapping

When microservices communicate across process boundaries, network partitions and service outages are inevitable. The Proxy Pattern encapsulates communication with remote downstream services.

Inside QueryGateway.handle(), the gateway validates, admits, and routes through HttpOrchestratorClient to the Python orchestrator. If the Python process is crashed, restarting, or partitioned, the Java network stack throws a ResourceAccessException (e.g., Connection Refused).

Rather than leaking raw socket traces or generic 500 errors to the RM, the gateway intercepts these exceptions and translates them into a domain-specific OrchestratorUnavailableException, returning a clean, standardized HTTP 503: {"error":"orchestrator unavailable"}.

BFSI Real-World Equivalent
🏧 ATM Hardware Terminal Failure Masking

When you insert a debit card into an ATM, the ATM's front-end controller communicates with the bank's interbank switch. If the remote switch or telecommunication line is down, the ATM screen displays: "Service Temporarily Unavailable — Please try again later."

The ATM never displays a raw C++ memory fault or Java socket stack trace on the terminal screen. Mapping ResourceAccessException → HTTP 503 provides the exact same institutional resilience and operational security.

Concept 3 of 4

🎯 Keyword Routing — The Orchestrator's Job

The Python orchestrator acts as a deterministic dispatcher. In contrast to monolithic LLM routing (which incurs latency, token costs, and hallucinations), production banking workflows use strict, deterministic routing trees for regulated operations.

The routing function lowercases the prompt and applies a rigid priority hierarchy:

PrioritySpecialistTrigger Words
1 (Highest)eligibilityeligible, eligibility, loan, bureau, top-up, topup
2 (Medium)transactiontransaction, transactions, history, recent, last
3 (Default)policyAll other banking queries (fees, charges, guidelines, greetings)

Notice that "loan" belongs to ELIGIBILITY_WORDS. If an RM asks "What is the loan transaction fee?", eligibility rules trigger first, ensuring credit underwriting checks take precedence.

BFSI Real-World Equivalent
🏢 Bank Branch Helpdesk & Specialist Desks

When a customer enters a retail bank branch, the front reception desk (Orchestrator) listens to their intent. If the customer says "I want to check if I can get a top-up loan", they are directed immediately to the Credit Underwriting Desk (Eligibility).

If they say "Print my last 5 debit transactions", they are sent to the Teller Counter (Transaction). If they ask "What is your RTGS remittance charge?", they receive the Schedule of Charges (Policy). The receptionist does not answer; they direct the customer to the certified specialist.

Concept 4 of 4

🧩 Specialist Agents — Each Calls One MCP Tool

In micro-agent architecture, each agent possesses a single, tightly constrained responsibility. Specialists in agents.py do not maintain conversational memory or call arbitrary endpoints. Each specialist connects to exactly one governed MCP tool over HTTP JSON-RPC at POST /mcp:

  • Policy Specialist: Calls searchPolicies with the prompt query. Extracts policy excerpt.
  • Transaction Specialist: Calls getRecentTransactions with customerId and size: 5. Formats date, description, and amount.
  • Eligibility Specialist: Calls getCustomerProfile with customerId. Reads bureau score; verifies score ≥ 700 threshold.

Every specialist returns an identical, standardized contract: {"agent": str, "answer": str, "customerId": str}.

BFSI Real-World Equivalent
🏛️ Core Banking Domain Subsystems

Inside a tier-1 bank, no single departmental officer has omnipotent access across all core systems:

  • Loan Officer (Eligibility Agent) queries CIBIL/Experian credit score APIs via the loan origination system.
  • Teller (Transaction Agent) queries the ledger database via the Finacle/Flexcube transaction engine.
  • Product Manager (Policy Agent) queries the regulatory document repository.

Each specialist agent respects the boundary of its underlying subsystem, interacting purely via standardized tools.

What Java Handles (Port 8080)
  • Bearer Authentication: Intercepts Authorization: Bearer lab-token. Missing or invalid token halts immediately with HTTP 401.
  • Admission Control & Rate Limiting: Tracks per-RM token buckets (10 req/min) returning HTTP 429 with Retry-After: 60. Global shed returns Retry-After: 1.
  • Request Validation: Validates customerId and prompt are non-blank (HTTP 400). X-RM-Id is a header, validated in GatewayAuthFilter.
  • Proxy Dispatch: Serializes clean request to Python orchestrator; traps network faults and surfaces HTTP 503.
  • MCP Tool Host: Hosts searchPolicies, getRecentTransactions, and getCustomerProfile on internal POST /mcp.
What Python Handles (Port 8090)
  • Zero Auth Overhead: Trusts the internal boundary. Operates purely on pre-authenticated payloads forwarded from Java.
  • Keyword Routing: Evaluates lowercased prompt against ELIGIBILITY_WORDS, then TRANSACTION_WORDS, falling back to policy.
  • Specialist Dispatch: Hands query execution to the appropriate domain function.
  • HTTP JSON-RPC Tool Invocation: Calls mcp_tools.py to communicate back to Java's /mcp endpoint.
  • Response Synthesis: Formats raw tool JSON into human-readable answers (extracting policy excerpts, transaction strings, and bureau scores).
Security Boundary & Lab Simplifications

In this workshop deployment, two deliberate simplifications exist:

  • Hardcoded Token: The Bearer token is "lab-token". In production, this would be an RS256 JWT signed by an enterprise Identity Provider (e.g., Keycloak, Okta, Azure AD) with claims validated against RM entitlements.
  • Unauthenticated Internal /mcp: The POST /mcp endpoint does not require a Bearer token. It serves as an internal tool bus designed solely for the trusted Python orchestrator process on the internal loopback network. External clients cannot route to /mcp directly.

The gateway receives an authenticated QueryRequest and must forward it to the Python orchestrator using Spring Boot's modern fluent RestClient.

Implementation Requirements

  • Execute an HTTP POST to orchestratorUrl with MediaType.APPLICATION_JSON content type.
  • Transmit request in the HTTP body.
  • Retrieve and deserialize the response into an OrchestratorReply.
  • If the reply or body is null, throw OrchestratorUnavailableException.
  • Catch ResourceAccessException (e.g. connection refused when Python is offline) and throw new OrchestratorUnavailableException(ex).
  • Catch RestClientException (HTTP client errors) and throw new OrchestratorUnavailableException(ex).
src/main/java/com/meridian/lab45/security/GatewayAuthFilter.java | gateway/QueryGateway.java | orchestrator/HttpOrchestratorClient.java JAVA 
package com.meridian.lab45.gateway;

import com.meridian.lab43.LabProperties;
import com.meridian.lab45.model.OrchestratorReply;
import com.meridian.lab45.model.QueryRequest;
import org.springframework.http.MediaType;
import org.springframework.stereotype.Service;
import org.springframework.web.client.ResourceAccessException;
import org.springframework.web.client.RestClient;
import org.springframework.web.client.RestClientException;

@Service
public class GatewayAuthFilter extends OncePerRequestFilter {
    private final RestClient http;
    private final String orchestratorUrl;

    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain) throws IOException {
        this.http = restClient;
        this.orchestratorUrl = properties.orchestratorUrl();
    }

    public OrchestratorReply forward(QueryRequest request) {
        try {
            OrchestratorReply reply = http.post()
                    .uri(orchestratorUrl)
                    .contentType(MediaType.APPLICATION_JSON)
                    .body(request)
                    .retrieve()
                    .body(OrchestratorReply.class);
            if (reply == null) {
                throw new OrchestratorUnavailableException(
                    new IllegalStateException("empty orchestrator body"));
            }
            return reply;
        } catch (ResourceAccessException ex) {
            throw new OrchestratorUnavailableException(ex);
        } catch (RestClientException ex) {
            throw new OrchestratorUnavailableException(ex);
        }
    }
}
🏦 BFSI Architectural Note — Upstream Exception Isolation

In banking switch architectures, client-facing gateways must isolate backend service failures. If the Python orchestrator crashes, wrapping ResourceAccessException into OrchestratorUnavailableException ensures the controller surfaces a clean, audit-compliant HTTP 503 rather than an unhandled 500 error that triggers P1 infrastructure alerts.

Security Warning — Order of Filters

The HTTP 401 authentication check is performed in GatewayAuthFilter.doFilterInternal() before QueryGateway.handle() is reached. Never attempt to catch authentication exceptions inside forward() or return a fallback payload. Unauthenticated requests must never execute network I/O.

Task 2 · route() in app.py — Deterministic Routing (25 min)
File: python-orchestrator/orchestrator/router.py · Test: cd python-orchestrator && pytest tests/test_router.py -q

The orchestrator maps natural language prompts from relationship managers to domain specialists using strict keyword precedence rules.

Routing Rules

  • Evaluate prompt in lowercase: text = (prompt or "").lower().
  • If any word in ELIGIBILITY_WORDS is present, return "eligibility" immediately.
  • If any word in TRANSACTION_WORDS is present, return "transaction".
  • Otherwise, default to "policy" (handles fee queries, general FAQs, and greetings).
python-orchestrator/orchestrator/router.py PYTHON 
from fastapi import FastAPI
from pydantic import BaseModel
from agents import eligibility, policy, transaction

app = FastAPI(title="Orchestrator")

ELIGIBILITY_WORDS = ("eligible", "eligibility", "loan", "bureau", "top-up", "topup")
TRANSACTION_WORDS = ("transaction", "transactions", "history", "recent", "last")


def route(prompt: str) -> str:
    text = (prompt or "").lower()
    if any(word in text for word in ELIGIBILITY_WORDS):
        return "eligibility"
    if any(word in text for word in TRANSACTION_WORDS):
        return "transaction"
    return "policy"


class Query(BaseModel):
    # X-RM-Id comes from the request header, not the body
    customerId: str = ""
    prompt: str = ""


@app.post("/v1/route")
def handle(query: Query) -> dict:
    agent = route(query.prompt)
    if agent == "eligibility":
        return eligibility(query.customerId, query.prompt)
    if agent == "transaction":
        return transaction(query.customerId, query.prompt)
    return policy(query.customerId, query.prompt)
Why Eligibility Trumps Transaction

Consider the prompt: "Can this customer get a loan based on their recent transaction history?"
This prompt contains both "loan" and "transaction". Evaluating eligibility first ensures the request routes to credit underwriting rather than simply printing statements.

Each specialist agent accepts (customer_id, prompt, call=call_tool), invokes its specific MCP tool, and formats a structured response dictionary.

Specialist Specifications

  • policy(): Calls searchPolicies with {"query": prompt}. Returns excerpt in answer.
  • transaction(): Calls getRecentTransactions with {"customerId": customer_id, "size": 5}. Formats lines containing date/postedOn, description (must include GROCERY for Asha), and amount.
  • eligibility(): Calls getCustomerProfile with {"customerId": customer_id}. Checks if bureauScore ≥ 700. Formats answer stating eligibility and explicit score (e.g., 742).
  • Error Handling: If result["ok"] is False, return {"agent": <name>, "answer": result["error"], "customerId": customer_id}.
python-orchestrator/orchestrator/agents/ — specialists PYTHON 
"""Three specialists. Each calls one Java MCP tool and returns {agent, answer, customerId}."""

from __future__ import annotations

from typing import Any, Callable
from mcp_tools import call_tool

ToolFn = Callable[[str, dict[str, Any]], dict[str, Any]]

ELIGIBLE_SCORE = 700


def policy(customer_id: str, prompt: str, call: ToolFn = call_tool) -> dict[str, Any]:
    result = call("searchPolicies", {"query": prompt})
    if not result["ok"]:
        return {"agent": "policy", "answer": result["error"], "customerId": customer_id}
    excerpt = (result["data"] or {}).get("excerpt", "No policy excerpt found.")
    return {"agent": "policy", "answer": excerpt, "customerId": customer_id}


def transaction(customer_id: str, prompt: str, call: ToolFn = call_tool) -> dict[str, Any]:
    result = call("getRecentTransactions", {"customerId": customer_id, "size": 5})
    if not result["ok"]:
        return {"agent": "transaction", "answer": result["error"], "customerId": customer_id}
    rows = (result["data"] or {}).get("transactions") or []
    parts = [f"{row.get('postedOn', row.get('date', '?'))} {row.get('description')} {row.get('amount')}" for row in rows]
    answer = "Recent transactions: " + "; ".join(parts)
    return {"agent": "transaction", "answer": answer, "customerId": customer_id}


def eligibility(customer_id: str, prompt: str, call: ToolFn = call_tool) -> dict[str, Any]:
    result = call("getCustomerProfile", {"customerId": customer_id})
    if not result["ok"]:
        return {"agent": "eligibility", "answer": result["error"], "customerId": customer_id}
    data = result["data"] or {}
    score = int(data.get("bureauScore") or 0)
    name = data.get("customerName") or customer_id
    if score >= ELIGIBLE_SCORE:
        answer = f"{name} is eligible for the top-up loan; bureau score {score}."
    else:
        answer = f"{name} is not eligible for the top-up loan; bureau score {score}."
    return {"agent": "eligibility", "answer": answer, "customerId": customer_id}

Distributed Systems

CAP Theorem Deep Dive — Financial Consistency

In distributed architectures, the CAP Theorem (Eric Brewer) proves that under a network partition (P), a distributed system can guarantee Consistency (C) OR Availability (A), but never both.

Operation TypeChosen GuaranteeBehavior Under PartitionBanking Rationale
Read Operations (v1 Specialists)
Profile, Transactions, Policies		 AP (Availability + Partition Tolerance) Returns slightly stale cached data or last known ledger view. Relationship manager can continue advising customer. Stale profile view for a few seconds carries minimal financial risk.
Write Operations (Future Tools)
Payment Transfer, Account Debit		 CP (Consistency + Partition Tolerance) Fails fast with HTTP 503; refuses transaction until partition heals. Zero tolerance for double debits. In banking ledgers, availability MUST be sacrificed to prevent split-brain monetary loss.
Real-World Case: UPI Balance vs RTGS Transfer

When checking your balance on Google Pay or PhonePe (read operation), the system operates on AP. If one read replica is 50ms behind master, your balance might show Rs. 50,000 instead of Rs. 49,800. The user experience remains fast and functional.

However, when you execute an RTGS/NEFT interbank wire transfer (write operation), the switch operates on strict CP. Every participating node must acknowledge the lock via two-phase commit (2PC) or distributed consensus. If network latency spikes, the wire is paused. It never proceeds on stale state.

What "Giving Up C" Means in Practice

In v1, giving up C means accepting Eventual Consistency. If customer Asha Raman makes a debit card purchase at POS 1 second before the RM queries her account, the copilot might return her previous balance.

This trade-off is intentional: an AI advisory copilot requires low latency and high availability to assist human officers. Because v1 tools are strictly read-only, no ledger corruption can occur.

Architectural Review — 10 Production Scenarios

Scenario 1
Downstream Orchestrator Outage
What HTTP status code does the Java gateway return when the Python orchestrator process is stopped, and how is it mapped?
HTTP 503 Service Unavailable. In QueryGateway.handle(), OrchestratorUnavailableException is caught and QueryController formats a clean JSON body: {"error":"orchestrator unavailable"}.
Scenario 2
Dual-Keyword Prompt Routing
An RM prompts: "I need a top-up loan for my customer based on past transactions." Which specialist handles it, and why?
Eligibility Specialist. In app.py, the route() function evaluates ELIGIBILITY_WORDS before TRANSACTION_WORDS. Because "loan" matches first, it returns "eligibility" immediately. Credit underwriting priority intentionally supersedes ledger display.
Scenario 3
Extending Specialist Domains
If an engineering team adds an "insurance" specialist, what files in the Python orchestrator must change? Does Java change?
Only two Python files change: (1) app.py to add INSURANCE_WORDS and dispatch to the new agent; (2) agents.py to define insurance(). The Java Gateway requires zero modifications because it transparently proxies the request envelope without inspecting business domains.
Scenario 4
Token Stripping on Forward
The gateway forwards requests to Python without the Bearer token. Why is this considered safe in enterprise topologies?
The Python orchestrator operates inside an isolated, private microservice subnet. The Java gateway serves as the perimeter security gatekeeper (DMZ). Stripping tokens follows the principle of least privilege: downstream workers do not need credentials they do not verify, preventing credential leakage in downstream logs.
Scenario 5
Authentication vs Authorisation (401 vs 403)
What is the strict architectural distinction between HTTP 401 and HTTP 403 in the AI Gateway context?
HTTP 401 (Unauthenticated): The gateway does not know who the caller is (missing or malformed Bearer token).
HTTP 403 (Unauthorized / Forbidden): The gateway knows who the caller is (token is valid), but that authenticated RM lacks entitlements to access that specific customer's profile.
Scenario 6
Credit Bureau Score Boundary
If Asha Raman's bureau score returns as 699, what does the eligibility specialist return?
Not eligible. The threshold is ELIGIBLE_SCORE = 700. Evaluating 699 >= 700 yields False. The agent returns: {"agent": "eligibility", "answer": "Asha Raman is not eligible for the top-up loan; bureau score 699.", "customerId": "10428"}.
Scenario 7
Rate Limiting 429 Header Dynamics
When an RM makes 11 requests in 30 seconds, they receive HTTP 429 with Retry-After: 60. Where does "60" originate?
It originates from the token bucket rate limiter in AdmissionControl (configured in Lab 4.1/4.3). Each RM is granted a quota of 10 requests per 1-minute window (60 seconds). When exhausted, the header instructs the client to back off until the window rolls over.
Scenario 8
MCP Tool Error Trapping
What occurs if mcp_tools.py returns {"ok": False, "data": None, "error": "customer not found"}?
The specialist intercepts if not result["ok"] and returns {"agent": "eligibility", "answer": "customer not found", "customerId": customer_id}. The orchestrator does not throw a 500; it gracefully formats the business error string back to the gateway.
Scenario 9
Direct /mcp Invocations vs Ingress
Can an external frontend bypass /v1/copilot/query and call POST /mcp directly? Why or why not?
Never in production. POST /mcp is unauthenticated internal plumbing for microservices. If external frontends could hit /mcp, they would bypass rate limiting, token authentication, and audit logging. Ingress firewalls must block external access to /mcp.
Scenario 10
Where the LLM Fits in Module 5
This lab contains no LLM. Where will the model sit when we advance to Module 5?
Inside the Python specialists in agents.py. Instead of returning raw excerpts or simple strings, the specialist takes the retrieved banking data (tool context), injects it into a grounded prompt template, and invokes the LLM to generate an empathetic, conversational response for the RM.
